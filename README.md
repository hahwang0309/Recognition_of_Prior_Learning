# K-RPL — 일학습병행 선행학습인정 심사 지원 시스템

일학습병행 참여자가 이미 갖춘 학습·경력을 NCS 능력단위와 대조해 훈련시간 면제를 심사하는 업무를 지원하는 웹 시스템이다. 제출 서류에서 근거를 찾아 능력단위별로 정리하고 판정 권고를 계산하며, **최종 판정은 심사위원이 한다.**

| 항목 | 내용 |
|---|---|
| 발주 과제 | 고용노동부 정책연구 「일학습병행 RPL 메커니즘 구축 방안 마련」 |
| 수행 | 한국직업능력연구원 |
| 버전 | 0.1.0 · 심사 기준서 v0.2 (2026-10-07) |
| 구성 | 웹 서버(FastAPI) · PostgreSQL · Claude API(근거 분석) |

---

## 1. 핵심 기능

| 기능 | 하는 일 | AI 사용 |
|---|---|---|
| **서류 접수** | pdf · hwp · hwpx · docx · txt · md 를 받아 문서 종류와 신뢰도 등급(A~E)을 붙이고 문장·행 단위로 나눈다. 파일명으로 종류를 추정한다 | 없음 |
| **기록 확인** (Track A) | 과정평가형 자격·NCS 훈련이수증의 능력단위 코드를 목표 종목과 대조하고, 이수시간 ÷ 요구시간으로 인정·보류·불인정을 가른다 | 없음 |
| **근거 분석** (Track B) | NCS 코드가 없는 학습·경력 서류의 문장을 능력단위의 **수행준거**에 배치하고 원문을 인용한다. 근거마다 직접·간접·부정을 표시한다 | 있음 |
| **수행준거 점수** | 수행준거마다 0·1·2 점을 규칙으로 매기고 능력단위 판정을 계산한다 | 없음(규칙) |
| **위원 검토** | 위원이 근거 원문을 보며 점수(Track B)나 추가 인정 시간(Track A)을 고치면 판정이 즉시 다시 계산된다 | 없음 |
| **확인 계획** | 보류 단위에서 확인이 필요한 수행준거를 면접·실기·시험으로 나누고 질문·과제 문안을 만든다 | 있음(1회) |
| **면제 결과·최종 판정** | 능력단위별 면제 시간과 남은 훈련 시간을 정리하고, 위원 합의 판정을 계산식과 함께 기록한다 | 없음 |
| **감사 기록** | 단계마다 입력·출력·AI 응답 원본을 해시와 함께 파일로 남긴다 | 없음 |

AI 산출물은 원문과 대조 검증되며, 인용이 원문에 없으면 다시 요청한다(최대 3회). 위원 입력은 AI 산출물을 덮어쓰지 않고 따로 쌓인다.

## 2. 심사 흐름

```
접수 ─→ ① 기록 확인 ─→ ② 근거 분석 ─→ ③ 위원 검토 ─→ ④ 확인 계획 ─→ ⑤ 최종 판정
        (자동, 규칙)    (AI, 필요 시)   (점수·시간 수정)  (보류 단위만)   (위원 합의 기록)
```

| 단계 | 누가 | 결과 |
|---|---|---|
| 접수 | 담당자 | 심사번호 발급, 서류 등록 |
| ① 기록 확인 | 시스템(자동) | 능력단위별 인정·보류·불인정 시간 |
| ② 근거 분석 | 시스템(AI) — 담당자가 시작 | 수행준거별 근거·점수, 능력단위 판정 권고 |
| ③ 위원 검토 | 심사위원 | 수정된 점수·추가 인정 시간, 재계산된 판정 |
| ④ 확인 계획 | 시스템(AI) — 위원이 「제출」 | 면접 질문·실기 과제·시험 범위 |
| ⑤ 최종 판정 | 심사위원 합의 | 면제 시간 확정, 판정 기록 |

## 3. 판정 기준

판정 규칙과 수치는 모두 `config/rubric/v0.2.yaml` 한 곳에서 읽는다. 아래 값을 바꾸려면 이 파일만 고치면 화면과 계산이 함께 바뀐다.

### 기록 확인 (Track A)

| 이수시간 ÷ 요구시간 | 판정 | 면제 |
|---|---|---|
| 100% 이상 | 완전충족 → **인정** | 요구시간 전체 |
| 50% 이상 | 조정범위내 → **인정** | 요구시간 전체 |
| 30~50% | **보류** | 위원 판단 |
| 30% 미만 · 미이수 | **불인정** | 없음 |

- 능력단위 코드 10자리가 같아야 대조한다(버전 무시).
- 이수시간은 과정평가형 편성기준과 훈련이수증 추출값 중 큰 쪽을 쓴다.
- 부족한 단위는 위원이 추가 인정 시간을 적는다. 이수 + 추가 ≥ 50% 면 요구시간 전체 면제, 미만이면 0 이다.

### 근거 분석 (Track B)

| 수행준거 점수 | 기준 |
|---|---|
| 2 | 그 일을 했다는 **직접 근거**가 1건 이상 |
| 1 | 관련은 있으나 증명은 못 하는 **간접 근거**만 있음 |
| 0 | 근거 없음, 또는 「배운 적 없다」 같은 **부정 진술** |

| 능력단위 판정 | 기준 (현재값) |
|---|---|
| 인정 | 수행준거 점수 평균 **1.3 이상** |
| 보류 | 평균 **1.0 이상** — 확인 계획 대상 |
| 불인정 | 평균 1.0 미만 |

- 이미 이수한 것으로 기록된 요소의 수행준거는 규칙으로 2점이다.
- 위원이 고친 점수가 AI 점수보다 우선한다.
- 문턱(1.3 / 1.0)을 포함한 미확정 기준 9건은 기준서의 `pending_decisions` 에 있다. 운영 환경(`KRPL_ENV=prod`)은 미확정 기준이 남아 있으면 기동하지 않는다.

### 필요한 것

| 항목 | 요구 |
|---|---|

| Python | 3.12 이상 |

### 처음 한 번

모든 명령은 이 저장소 최상위(`App/`)에서 실행한다.

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"     # 패키지 설치
cp .env.example .env                                             # 설정 파일 만들기 — 아래 「설정」 참고
./scripts/dev.sh db                                              # PostgreSQL 기동
./scripts/dev.sh migrate                                         # 표 만들기
./scripts/dev.sh seed --src /경로/NCS카탈로그폴더                  # NCS 카탈로그 적재 (krpl.sqlite·ncs_ksa.sqlite 가 있는 폴더)
./scripts/dev.sh env                                             # 설정 반영 확인 (키는 가려서 출력)
```

## 5. 실행과 종료

```bash
./scripts/dev.sh db        # ① DB 켜기
./scripts/dev.sh up        # ② 웹 서버 + 판정 작업기 켜기
```

브라우저에서 **http://localhost:8000** 을 연다. 끌 때는 서버 터미널에서 `Ctrl+C`.

| 명령 | 용도 |
|---|---|
| `./scripts/dev.sh up` | 웹 서버와 판정 작업기를 함께 켠다. 화면에서 「근거 분석 시작」을 누르려면 이것을 쓴다 |
| `./scripts/dev.sh api` | 웹 서버만 켠다. 판정을 아래 명령줄 방식으로 돌리고 화면은 보기만 할 때 |
| `./scripts/dev.sh test` | 자체 시험 실행(별도 시험용 DB 사용) |

## 6. 사용 방법

### 화면에서 한 건 심사하기

1. **새 접수** — 홈의 「새 접수 시작」 → 심사번호(자동 제안)·목표 종목·보유 자격을 넣는다.
2. **서류 올리기** — 파일을 끌어다 놓고 문서마다 종류와 신뢰도 등급을 확인한다. 올리면 기록 확인이 자동으로 돈다.
3. **근거 분석 시작** — 심사 개요의 「② 근거 분석 시작」을 누른다(접수 현황의 「다음 할 일」 버튼으로도 된다). 진행률이 표시되며 한 건에 4~10분 걸린다. 경력·학습 서류가 없거나 기록 확인으로 모두 덮이면 이 단계는 「해당 없음」이다.
4. **위원 검토** — 심사 개요의 링크로 위원 페이지를 연다.
   - 기록 확인(Track A): 부족 단위에 추가 인정 시간을 적는다.
   - 근거 분석(Track B): 능력단위를 펼쳐 수행준거마다 0·1·2 를 누른다. 근거 인용을 누르면 문서 열람창에서 원문이 강조된다. 바꾸는 즉시 저장되고 판정이 다시 계산된다.
5. **확인 계획** — 위원 페이지의 「제출」. 포함할 보류 단위를 고를 수 있다. 보류 단위가 없으면 AI 를 부르지 않는다.
6. **최종 판정** — 면제 결과 화면의 「판정 기록」에 위원 합의 판정·인정 시간·사유를 적는다. 계산값이 미리 채워져 있고, 고친 값은 계산값과의 차이와 함께 기록된다.

### 명령줄로 여러 건 처리하기

```bash
# 접수 — 문서별 파일이 든 폴더를 그대로 받는다 (00_ 로 시작하는 파일은 제외)
.venv/bin/python scripts/load_candidate.py --src "/경로/지원자폴더" --case R2026-0001 --program 건축설계_L3

# 근거 분석 — 여러 건을 이어서 돌릴 수 있다
.venv/bin/python scripts/assess.py R2026-0001 R2026-0002
.venv/bin/python scripts/assess.py R2026-0001 --force          # 이미 판정된 건을 다시

# 인쇄용 정적 보고서 — storage/reports/ 에 생성
.venv/bin/python scripts/make_report.py
```

### 위원에게 열람 전용으로 보여 주기

위원 페이지 주소 끝에 `?ro=1` 을 붙이면 점수·시간 입력과 제출이 막힌 열람 전용 화면이 된다. 외부에 공개할 때는 내부망이나 접속 인증이 있는 터널을 사용한다.

## 8. 설정

### `.env` — 비밀값과 환경마다 다른 값

| 변수 | 뜻 |
|---|---|
| `KRPL_ENV` | `local` · `staging` · `prod` · `test` |
| `KRPL_DATABASE_URL` | PostgreSQL 접속 문자열 |
| `ANTHROPIC_API_KEY` | Claude API 키. 비우면 실제 호출을 하지 않는다 |
| `KRPL_LLM_BACKEND` | `anthropic`(실제 호출) · `replay`(저장 응답 재생, 비용 0). 비우면 키 유무로 정한다 |

`.env` 는 저장소에 올라가지 않는다. 적용 순서는 `config/settings.yaml` < `config/environments/{환경}.yaml` < `.env` < 실행 시 환경변수다.

### `config/` — 심사 기준과 AI 설정

| 파일 | 내용 |
|---|---|
| `rubric/v0.2.yaml` | **심사 기준의 단일 출처** — 판정 문턱, 점수 규칙, 문서 종류·신뢰도 등급, 미확정 기준 |
| `models.yaml` | AI 모델과 호출 설정, 비용 상한(건당 $5 · 하루 $100 초과 시 관리자 승인) |
| `prompts/trackb_v6.md` | 근거 분석 지침 |
| `prompts/trackb_plan.md` | 확인 계획 문안 지침 |
| `exams.yaml` | 확인 계획에서 안내하는 시험(큐넷 출제기준 링크) |

## 9. 처리 비용과 시간

기본 모델은 `claude-haiku-4-5` 이다. 가상 사례 17건 실측(2026-10-02) 기준이다.

| 작업 | 비용 | 시간 |
|---|---|---|
| 근거 분석 1건 | $0.41 ~ 1.46 | 4 ~ 10분 |
| 근거 분석 17건 합계 | $13.59 | 99분 |
| 확인 계획 1회 | $0.07 ~ 0.08 | 1분 안팎 |
| 기록 확인 | 없음 | 즉시 |

비용은 제출 서류 양과 능력단위 수에 비례한다. 상위 모델이 필요하면 `assess.py --profile trackb_assess_opus` 로 바꾼다.

## 10. 감사 기록

심사 한 건의 모든 단계가 `storage/audit/{심사번호}/` 에 파일로 남는다. 접수 단계(문서 목록, 개인정보 가림 기록, 조각, 이수 기록 추출)와 판정마다(AI 입력 꾸러미, 적용 지침, 기준 요약, AI 응답 원본, 검증 결과)가 해시와 함께 저장된다. 화면의 「감사」에서 열람한다. 최종 판정 기록에는 적용 규칙, 능력단위별 인정 현황, 그 시점의 미확정 기준 목록이 함께 저장된다.

`storage/` 에는 제출 서류가 들어가므로 저장소에 포함하지 않는다(`.gitignore`).

## 11. 문제 해결

| 증상 | 조치 |
|---|---|
| 화면이 안 열림 | `./scripts/dev.sh db` 후 `./scripts/dev.sh up`. 포트 8000 이 쓰이고 있으면 `lsof -i :8000` 으로 이전 서버를 끈다 |
| 「판정 작업기가 돌고 있지 않습니다」 | `api` 대신 `up` 으로 켜거나 다른 터미널에서 `./scripts/dev.sh worker` |
| 근거 분석이 저장 응답으로만 돎 | `./scripts/dev.sh env` 로 키 반영 확인. `KRPL_LLM_BACKEND=anthropic` 으로 지정 |
| 운영 환경에서 기동 거부 | 기준서의 미확정 기준(`pending_decisions`)을 확정하거나 `KRPL_ENV=staging` 으로 운영 |
| DB 가 안 뜸 | `/tmp/pg15.log` 확인 |
